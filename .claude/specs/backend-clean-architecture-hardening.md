## 1. Goal

The backend audit (this session) found a **structurally excellent** codebase — zero import-law violations, zero layer inversions inside modules, 72/72 injectables with explicit tokens, one error hierarchy, one envelope — sitting next to a handful of serious, isolated defects: a whole `/api/users` CRUD surface with no tenant scoping (a cross-tenant account takeover, currently unreachable only because a one-character bug in `user.routes.ts` makes every request hang), a PII log, an open SSRF surface the security doc already names, template leftovers (dead encryption service, 15 unused runtime deps incl. `stripe`/`pdf-*`/`ffmpeg`), and **no Dockerfile / no CI workflows** even though `docker-compose.local.yml`, `docker-compose.prod.yml`, `DEPLOY.md` and `scripts/*.mjs` are all coded against them. The outcome of this task is a backend that is safe to deploy multi-tenant, buildable and shippable end-to-end with the tooling the repo already documents, with its config, chassis and docs describing exactly the code that exists — without changing any HTTP contract the frontend or the public API consumes.

## 2. Scope

**In:**
- **Security (blocking):** remove the unscoped `/api/users` CRUD surface (use cases, controller, routes, DTO, the `/users` mount) and its now-orphan repository methods (`findAll`, `findByIds`, hard `delete`); drop the raw e-mail from the password-reset log and add `email` to the pino redaction list; SSRF guard on the webhook sender (private/loopback/link-local/multicast block after DNS resolution, at every attempt, `redirect: "manual"`, 3xx = non-retriable rejection); avatar upload derives the S3 key extension and `ContentType` from the validated MIME allowlist, never from `originalname`.
- **Dead code:** `core/service/aes-gcm-encryption.service.ts` (+spec), `shared/provider/encryption-provider.interface.ts`, the two `AesGcm*` DI tokens; `DEFAULT_PROFESSIONAL_COLOR`; the stale orphan `shared/provider/domain-event-bus.interface 2.ts`; `core/http/controllers/index.ts` (a `core → modules` layer inversion with zero consumers); the stray root `package-lock.json` (the project is yarn); 15 never-imported runtime deps (`@bull-board/api`, `@bull-board/express`, `@signpdf/placeholder-plain`, `@signpdf/signpdf`, `@signpdf/utils`, `chardet`, `exceljs`, `ffmpeg-static`, `fluent-ffmpeg`, `libphonenumber-js`, `mammoth`, `papaparse`, `pdf-lib`, `pdf-parse`, `pdf-to-img`, `stripe`) and their `@types/*`.
- **Domain / consistency (within `backend.md`'s "entities have no behavior" rule):** `UserStatus` moves from `shared/type/enums.ts` to `modules/user/domain/value-object/user-status.ts` (the convention `devices`/`messaging` already follow; `backend-modules.md` wins over `backend.md`'s "enums in shared/type"); `User.status` getter typed as `UserStatusType` (today it is `string`, which is why the literal `"ACTIVE"` compiled); read-only predicates `User.isActive` and `Device.isConnected` replace the status comparisons duplicated across 5 use cases; `shared/dto/common.dto.ts` with `uuidParamSchema()` replaces the 4 remaining copies; `auth/application/service/auth/` flattened to `auth/application/service/`; `AuthProfileBuilder` registered by `auth.module.ts`, not by `core/container`; `DEFAULT_LOCALE` imported from `shared/constant`, not redeclared.
- **Chassis:** `main.ts` reduced to bootstrap; graceful shutdown + `unhandledRejection`/`uncaughtException` handling extracted to `core/service/lifecycle/`; `core/http/index.ts` barrel no longer re-exports module controllers.
- **Config:** `core/config/env.ts` composed from per-concern schemas in `core/config/schema/*.schema.ts` (same `env.X` surface, zero consumer changes); `.env.example` synced with the schema and a spec that fails when they drift again.
- **Docker + CI:** `apps/api/Dockerfile` (multi-stage: `deps` → `build` → `runtime`; node 20 alpine; yarn workspaces; `@pombo/shared-types` built; `prisma generate`; `tsc && tsc-alias`; production deps only; non-root user; `wget` for the healthcheck; `APP_VERSION` build-arg; entrypoint runs `prisma migrate deploy` then `node dist/main.js`; `EXPOSE 3333`; `HEALTHCHECK /healthz`), root `.dockerignore`, `docker-compose.local.yml` pointed at the `dev` stage, `.github/workflows/build-api.yml` and `deploy-api.yml` implementing exactly the contract `scripts/lib/deploy-cli.mjs` + `docker-compose.smoke.yml` + `infra/app/setup-github-runner.sh` encode.
- **Guards + docs:** new checklist code `B-C14` (middleware factory passed to `router.use` without invocation) + grep rule in `post-edit-backend.sh` + a route-mount contract spec; `backend-modules.md` canon gains `domain/value-object/`, `application/listener/`, `infrastructure/job/`, `infrastructure/health/`; `backend.md` drops `controllers/index.ts`, the AES row, "enums" from `shared/type`, and gains the `toMetadata()` naming note + a real `shared/dto`; `B-M1`/`B-M9` reworded to match reality; `DEPLOY.md`/`infra` comments updated for the single multi-stage Dockerfile.

**Out (deferred):**
- **Rich domain model** (behavior/transitions inside entities, `DeviceStatus`/`MessageStatus` as classes). `backend.md` § Entity explicitly forbids it today. Changing that is an architecture decision for the owner, not a refactor; this PR does the maximum the current rule allows.
- Rewriting `auth`'s 13 specs from `vi.fn()` mocks to in-memory fakes. Both styles are now documented as sanctioned; unifying is churn with no behavioral payoff.
- `@langchain/*` and `openai` deps: declared-but-unused **by design** (`backend.md` § Stack — `/ai-backend` owns that foundation). Kept.
- `apps/web` — untouched. `packages/shared-types` — untouched (`UserResponseDTO` may still be consumed by the web app's contracts).
- Splitting `core/http/app.ts` (helmet/CSP/CORS into a `security.middleware.ts`) — cosmetic; the file is already well-structured.
- Integration tests that boot Express + Postgres (a real gap — the route-mount contract spec closes the specific bug class cheaply; a supertest layer is its own task).
- Infra hosts (`ufw`, WireGuard, Caddy, backup) — `/devops` territory, unchanged.
- **A per-device "allow private webhook target" override for the SSRF guard.** The guard refuses every non-public address with no configuration path around it — the right default for a multi-tenant SaaS, but it does block a customer whose receiver lives on a private network (on-prem, VPN, a local receiver in staging). If such customers exist, the switch is a product decision (explicit warning + audit trail), not a refactor. Surfaced by the duck challenger; deferred, called out in the PR.
- **Content-level verification of uploaded images** (magic-byte sniffing / `nosniff` on the avatar origin). AC-5 closes the `originalname` vector by deriving the S3 key + `ContentType` from the allowlisted MIME header; the header itself stays client-declared and unverified. Deferred, called out in the PR.

## Risks & edge cases

| Risk | Prob. | Impact | Mitigation |
|---|---|---|---|
| Removing `IUserRepository.delete/findAll/findByIds` breaks a caller the grep missed | Low | Medium | `tsc` is the gate; `mockUserRepository` updated in lockstep |
| SSRF guard blocks a legitimate customer webhook on an internal/IPv6 range | Medium | Medium | Public ranges only are allowed; error is a typed 4xx-style rejection logged with the code, never retried; documented in `security.md` |
| DNS rebind TOCTOU between guard and `fetch` | Medium | Low | Re-resolve at every attempt right before `fetch`; residual window documented; `redirect: "manual"` closes the redirect vector |
| Dockerfile diverges from what `prisma-client` generator + `tsc-alias` need | Medium | High | AC-12 is an actual build + boot-smoke run locally, not a static check |
| Workflows reference a `vars.API_URL` that isn't set on the repo | High | Low | Documented in `RUNBOOK.md` § A; the deploy pre-flight fails fast with "PRODUCTION UNTOUCHED" (same posture the scripts already have) |
| Grouped env schemas change a default or a coercion | Low | High | `env.spec.ts` unchanged and green; the merged schema is diffed key-by-key against the old one in a one-off script during the task |
| Deleting `/users` surprises a consumer outside this repo | Low | Medium | Grepped web app, e2e, scripts, docs: zero. Listed in the PR under "Breaking" anyway |
