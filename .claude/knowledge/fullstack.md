## Contract / Integration Patterns
- **[High] Polymorphic outbox/queue: one generic use case + a shared type→handler dispatch, not N use cases.** When adding many variants that share a subtle write-before-send/idempotency/rate-limit/drain flow (e.g. the 6 rich WhatsApp send types), reuse the existing flow via ONE generic use case that stores a `type` discriminator + a `payload` JSON, and centralize the `type → gateway method` mapping in a single `dispatchOutboxSend(gateway, deviceId, row)` helper consumed by BOTH the live path and the drain. This guarantees a queued variant replays as its own type (never downgraded to the default) and is enforced by an exhaustive `switch`, not convention. Guard the discriminated column with a DB CHECK constraint (`text` XOR `payload`) — Prisma doesn't model CHECK, so add it in the migration + a `///` note in schema.prisma.
- **[High] Idempotency over a JSON payload needs an order-independent compare.** Postgres jsonb does not preserve key order, so a naive `JSON.stringify(existing) === JSON.stringify(incoming)` yields false conflicts on reordered keys. Use a recursive key-sorting `stableStringify` (keep array order — it's semantic). Document that array order is significant for the caller's dedup.
- **[High] Migration convention here = single regenerated `_first` baseline (dev-zero), not incremental folders.** Git history squashes all migrations into `_first`; regenerate it with `prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script` rather than adding an ALTER migration. `migration-safety` will (correctly for a live-data repo) suggest regenerating the baseline — verify the convention via `git log` on the migrations dir first.
- **[STALE 2026-09-16] BE/FE type mirrors are manual.** Superseded: the device/message/token contract, the status unions and `ErrorCodes` now live in `@pombo/shared-types` (see next entry). Only types the web does not consume (e.g. the public `/api/v1` DTOs) are still API-only.
- **[High] The wire contract is `@pombo/shared-types`; the pin is a spec, not a comment.** Unions are `as const` arrays in the package (`DEVICE_STATUSES` → `DeviceStatus`), re-exported by the API domain; a `*-status.spec.ts` compares the array with the Prisma enum at runtime AND `expectTypeOf<Union>().toEqualTypeOf<prisma_enum>()` at type level. Request schemas are pinned with `expectTypeOf<z.input<typeof Schema>>().toEqualTypeOf<RequestDTO>()` — use `z.input`, not `z.infer` (the client sends the input side). The API `tsconfig` includes specs, so `yarn type-check` enforces the type half; prove it once with a throwaway failing probe.
- **[High] The shared-types "response DTO" must describe the controller body, not the use-case output.** The package said the sign-in body had `refreshToken`; the controller actually writes `{ user, token, csrfToken }` and keeps the refresh token in the cookie. Keep use-case results (with the refresh token) as API-internal types and put `satisfies ApiSuccessResponse<Dto>` on the controller body so the drift can't come back.
- **[High] The web consumes `@pombo/shared-types` from its TS source (alias in `apps/web/aliases.ts` + `tsconfig` paths), never through Vite's dep pre-bundle.** A linked workspace package in `optimizeDeps.include` is NOT re-optimized when its `dist` changes (Vite only hashes lockfile/config): adding `ErrorCodes` left a stale bundle without the export and the app rendered blank in dev and e2e while unit tests and `vite build` stayed green. The CJS `dist` exists only for the API (`require`).
- **[High] When a use case grows a new branch that reuses a shared `bus.publish`, audit EVERY path that publishes the same event — including the drain/retry path.** Adding a group-send branch to `SendTextMessageUseCase` made the live path emit the group JID on `message.sent.phone`, but `DrainOutboxUseCase` still called `userJidToPhone(toJid)` and silently stripped `@g.us` off a queued-then-drained group message. Grep for the parallel event-payload derivation in the drain the moment you change the live one; add a drain regression test asserting the queued variant replays with the identical payload shape.
- **[High] A picker fed by a BE list endpoint must accept back EVERYTHING that endpoint can return.** The group `SelectField` was populated from `GET /devices/:id/groups`, but the send DTO validated `groupJid` with a stricter regex (`/^[\d-]+@g\.us$/`) than the list could surface — a valid group would be listed yet rejected on send (422). Rule: when a value round-trips list→pick→send, the send validator's accepted set must be a SUPERSET of the list's output. Validate by shape/suffix (`/^[^@\s]+@g\.us$/`), not by an assumed narrow id format.
- **[Med] Mutually-exclusive optional DTO fields → discriminated union with `?: never`, never two `?:` optionals + a `!` assertion.** `SendTextInput` as `{phone?; groupJid?}` let a caller pass neither and collapse to an `undefined` JID at runtime. `(Base & {phone:string; groupJid?:never}) | (Base & {groupJid:string; phone?:never})` makes both/neither a compile error and lets the use case narrow on `if (input.x != null)` with zero non-null assertions in the branches.
- **[Med] A `useQuery` on a live-connection-gated endpoint (503 when the socket is down) needs `retry: false` + a distinct `isError` render state.** Default TanStack retry (3×) hammers a device known-offline; and folding the error state into the empty-list placeholder ("no groups found") hides the real cause. Give socket-gated reads `staleTime: STALE_TIMES.volatile` + `retry: false` and a dedicated error placeholder key in all 3 locales.
